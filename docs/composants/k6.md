# k6 (tests de charge)

**Couche** : Outillage et CI · **Où** : poste opérateur (idéalement depuis NetBird) · **Version** : k6 du devshell (`flake.lock`)

## À quoi elle sert ici et pourquoi ce choix

Valide que la plateforme tient la charge d'un événement : un seul script `tests/load/pad.js` joue quatre scénarios en parallèle (navigation, soumissions de flags, flux SSE du scoreboard, démarrage, prolongation
et arrêt d'instances). Il sert aussi à régler les seuils KEDA.

## Où elle tourne et comment elle est déployée

Exécuté à la demande : `task load` (profil `smoke` par défaut) ; `PAD_PROFILE=load` ou `stress` pour 50 ou 200 VUs.

## Version épinglée

Binaire `k6` du devshell ([Nix](nix.md)) ; la CI ne fait que `k6 inspect`.

## Fichiers de configuration dans le dépôt

`tests/load/pad.js`, `tests/load/README.md` ; variables `PAD_BASE_URL`, `PAD_CTFD_URL`, `PAD_TOKENS` ou `PAD_SSO_SECRET`, `PAD_PROFILE`.

## Interactions avec les autres briques

Cible le [front](frontend.md) et [CTFd](ctfd.md) (y compris [chall_manager_bridge](ctfd-plugin-chall-manager-bridge.md)) ; les joueurs de test sont créés par `POST /api/v1/sso/session`.

## Sécurité

Aucun token ni secret n'est commité. L'appelant doit être dans `PAD_SSO_ALLOWED_CIDRS` pour créer des joueurs ; sinon fournir des tokens existants.

## Supervision

Observer pendant le test les dashboards `pad-live-ctf` et `pad-capacity`, et le comportement de [KEDA](keda.md) et du [cluster-autoscaler](cluster-autoscaler.md).

## Opérations courantes

```bash
task e2e -- up && task e2e -- seed     # pile locale
set -a; . .state/e2e.env; set +a
task load
PAD_PROFILE=load task load
```

## Pièges connus

Le TTL par défaut d'un token est de 900 s : pour une campagne longue, fournir des tokens valides pendant toute la durée. Ne jamais lancer `stress` sur un événement réel.
